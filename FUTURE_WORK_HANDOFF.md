# Magic Animals — план персонажей и будущих игр

Этот файл нужен, чтобы продолжить работу в другом сеансе Codex без пересказа
договорённостей. Он фиксирует пожелания пользователя и известное состояние
репозитория на 30.09.2026. Фактический код и результаты проверок перед работой
нужно сверить с текущим Git и документацией.

## Главный приоритет сейчас

Довести **Magic Animals** и прежде всего CAT / Milo. Не начинать массовое
обновление других животных, пока пользователь явно не утвердит готового CAT
как визуальный эталон. Не выпускать незавершённый этюд вместо работающей модели.
Существующие интерфейс, игровые механики, камера, TV-сопряжение и ISP-настройки
должны продолжить работать. Физические тесты на iPhone/iPad/TV пользователь
предложил провести позднее.

Пользователю понравился оригинальный [turnaround Milo](assets/characters/cat/concepts/milo-turnaround-v1.png):
кремово-персиковый пушистый котёнок, выразительные бирюзовые глаза и сиреневое
худи на молнии. Это художественный референс, а не готовая 3D-модель. Нужна
самостоятельная редактируемая 3D-модель в Blender: аккуратный силуэт спереди,
сбоку и сзади; естественная более выразительная мордочка и рот; настоящие
отдельные глаза, веки и радужка; мягкая стилизованная шерсть; тканевое худи;
разделённые руки и ноги; скелет и заметно разные движения Idle, Happy, Wave,
Jump, Run, Sleep, Roar. Затем оптимизированный GLB для Safari, desktop и TV.
Вдохновение — качественная семейная стилизованная 3D-анимация, без копирования
чужого персонажа, голоса или дизайна.

Пользователь отказался от Meshy. Локально установлен официальный Blender MCP и
исследуется открытая MIT-модель TripoSR как **черновой источник формы**.
`assets/characters/cat/milo-authoring.blend` — отдельный процедурный этюд,
который всё ещё выглядит слишком игрушечно. `milo-reconstruction-256.blend` —
сырая реконструкция по оригинальному изображению; силуэт ближе к референсу,
но сетка неровная, глаза и одежда не отделены, нет ворса и рига. Обе сцены
**не утверждены** и не должны подменять текущую модель в игре. Подробности,
запуск и ограничения — [BLENDER_WORKFLOW.md](BLENDER_WORKFLOW.md), критерии —
[CAT_ART_HANDOFF.md](CAT_ART_HANDOFF.md). Просмотр импортированного GLB:
`/__cat-import-review` на локальном dev-сервере.
Проба накладных глаз `milo-eye-study.blend` также **отклонена** после рендера:
глаза выглядят чужеродно. Нужна переработка формы лица и посадки глаз, а не
ещё один слой деталей поверх сырой сетки.

## После утверждения CAT: единый состав

Порядок: **FOX → DOG → LION → RABBIT → BEAR → PANDA → ELEPHANT**. Все восемь
друзей должны ощущаться персонажами одного мультфильма: близкий уровень
рендеринга, пропорции (крупная голова, компактное тело, короткие лапы),
выразительные глаза, мягкий стилизованный мех, тканевая одежда, общий свет,
PBR-материалы, подход к ригу, экспорт и анимациям. Создавать каждого с нуля
несовместимым способом нельзя; качество CAT при переносе системы не снижать.

| Друг | Сохраняемый видовой признак | Вариация одежды из арт-направления |
| --- | --- | --- |
| FOX / Foxy | острая мордочка и уши, пушистые щёки, большой хвост | уютная зелёная или оранжевая толстовка |
| DOG / Bubbles | широкая дружелюбная морда, собачьи уши и нос | голубая толстовка |
| LION / Sunny | округлая мягкая грива, тёплая палитра | жёлтая или бежевая толстовка/жилетка |
| RABBIT / Poppy | длинные мягкие уши, лёгкий пружинистый силуэт | пастельная толстовка |
| BEAR / Maple | круглая голова, небольшие уши, более плотное тело | тёмно-зелёная или коричневая одежда |
| PANDA / Pebble | чёрно-белые пятна, в том числе вокруг глаз | светлая толстовка |
| ELEPHANT / Ellie | большие уши, короткий стилизованный хобот | голубая одежда |

Для каждого нужны семь отчётливых анимаций, отдельные добрые звуки и свой
мультяшный **оригинальный** голос. Движения тоже озвучиваются; английские слова
и фразы должны звучать правильно и увлекательно для ребёнка около трёх лет.
Сейчас локальные голосовые файлы и задания на слух уже есть; их интонацию и
понятность ещё нужно оценить на слух. См. [AUDIO_PRODUCTION.md](AUDIO_PRODUCTION.md).
Для WebAR новые физические карточки FOX, RABBIT, BEAR, PANDA, ELEPHANT пока не
подключены: текущее распознавание работает для CAT, DOG, LION. Новые цели надо
делать и проверять отдельно, без подмены распознавания таймером.

## Будущая серия игр — идеи, не текущая реализация

Первое исходное задание прямо называет Magic Animals фундаментом серии и
просит **сейчас не реализовывать** следующие игры. Сохраняем список как
планирование, без предположений о ещё не согласованных механиках:

1. Birthday Adventure
2. Dinosaur Eggs
3. Monster Restaurant
4. Magic Farm
5. Space Mission
6. Color Hunt
7. Teddy Hide & Seek
8. Bubble Catch
9. Dance With Foxy
10. Другие идеи по мере согласования

Для продолжения серии использовать проверенные границы архитектуры Magic
Animals: Web/PWA для Safari, `GameEngine` отдельно от AR-провайдера,
конфигурацию персонажей и звука, реальное распознавание напечатанной цели там,
где его требует игра, понятный fallback без камеры, самостоятельную TV-сцену
и добровольное QR/шестизначное сопряжение. Детская логика: удивление → действие
→ английское слово → персонаж → эмоция → повторение → награда; без оценок,
таймера, наказания и обязательного чтения. Проект будущей игры начинать с
отдельного описания сценария и согласования с пользователем, не придумывать
его как уже принятое решение.

Для **Birthday Adventure** в исходном задании уже было рабочее название
**The Lost Birthday Star**. При проектировании общей архитектуры нужно
сохранять возможность переиспользовать распознавание карточек, порталы,
персонажей, частицы, звук, `TVBridge`, переходы сцен, родительский режим и
офлайн-кэш. Саму Birthday Adventure пока не реализовывать.

## Как подхватить работу в новом Codex

1. Открыть `C:\Work\Codex\KidsGame`, проверить `git status`, прочитать
   [README.md](README.md), [ARCHITECTURE.md](ARCHITECTURE.md),
   [GAME_DESIGN.md](GAME_DESIGN.md), [RUN_GUIDE.md](RUN_GUIDE.md) и этот файл.
2. Посмотреть утверждённый 2D-референс и настоящий 3D-рендер со всех ракурсов.
   Не принимать технические метрики за художественную приёмку.
3. Довести CAT локально, сделать риг/анимации/оптимизированный GLB, проверить
   страницу просмотра и показать пользователю. **Дождаться утверждения CAT**.
4. После приёмки перенести тот же производственный подход на остальные семь
   видов в указанном порядке. Проверить производительность Safari и TV.
5. Затем вернуться к сценарию и отдельному плану будущей игры из списка.

Публикация исходников предназначена для GitHub `lvipa/magic-animals`, но
локальные файлы доступа, ключи, окружения `.tools/`, `.test-artifacts/`,
снимки ISP и любые секреты не публиковать. Файл `доступ ssh.txt` находится
только локально и игнорируется Git. TV-код остаётся частью приложения:
пользователь просил сохранить его вместе с QR-подключением; это не пароль
учётной записи. Существующие настройки ISP без отдельной необходимости не
менять.

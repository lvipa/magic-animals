# Milo: локальный Blender и официальный MCP

Работа продолжается без Meshy. Платный сервис и API-ключ не нужны.
Используется [официальный Blender Lab MCP](https://www.blender.org/lab/mcp-server/),
версия **1.0.3**, и портативный Blender **5.1.2** для Windows x64.
MCP позволяет выполнять операции над сценой; художественное качество проверяется
по настоящим рендерам и деформации модели.

## Текущее состояние

- Утверждён **2D-образ** Milo в `assets/characters/cat/concepts/`.
- Новая отдельная сцена — `assets/characters/cat/milo-authoring.blend`.
  В ней упакованы референсы, есть контрольная сетка головы с соединёнными
  корнями ушей, веки, отдельные глаза/радужки, нос, усы и кривые ворса.
  Добавлены соединённая анатомическая сетка тела/лап, отдельная одежда с
  рукавами, капюшоном, манжетами, карманами, молнией и пушистый хвост.
- Это **незавершённый художественный этюд**, не принятая модель.
  Финальная доводка формы, UV для шерсти, риг, мимика, анимации и экспорт ещё предстоят.
  Посадка глаз, мордочка, корни ушей и ткань требуют доводки по референсу.
- Сцена не заменяет `milo-master.blend` или `public/models/cat-studio.glb`.
  Приложение пока использует прежний CAT. Другие животные ждут приёмки CAT.

## Подготовка на другом Windows-компьютере

Нужны Git, Python 3.10+ и PowerShell. Из корня репозитория:

```powershell
./scripts/prepare-blender-mcp.ps1
```

Скрипт устанавливает всё в игнорируемую `.tools/`, проверяет SHA-256 архива
Blender и commit официального MCP. Существующую несовместимую копию MCP
не перезаписывает. Аддон не устанавливается в обычный профиль Blender.

Закреплённые исходники:

- Blender: `https://download.blender.org/release/Blender5.1/blender-5.1.2-windows-x64.zip`
- SHA-256: `345bedea7b0acf7cc9666423d8553f9129622aea34ded65c23e8cb70f83f14ff`
- MCP: `https://projects.blender.org/lab/blender_mcp`, tag `v1.0.3`
- Commit: `2cea8d566dde07fbac28a61d698909d69724e853`

## Запуск сцены и моста

Один процесс за раз; адрес только `127.0.0.1:9877`.
Для работы с видимым окном Blender:

```powershell
& './.tools/blender-5.1.2-windows-x64/blender.exe' --factory-startup --online-mode --python scripts/start-blender-mcp.py
```

Для фонового режима в отдельном терминале:

```powershell
& './.tools/blender-5.1.2-windows-x64/blender.exe' --background --factory-startup --online-mode --python scripts/start-blender-mcp.py
```

Сохраните сцену перед завершением. В окне Blender — закрытие окна;
в фоновом терминале — Ctrl+C. Не запускайте второй мост на занятом порту.
Параметр `--online-mode` нужен официальному аддону; мост привязан к loopback.

## Подключение к Codex

На текущем компьютере сервер уже зарегистрирован как `blender-local-milo`.
Для другого пути подставьте абсолютные пути своего проекта:

```powershell
codex mcp add blender-local-milo --env BLENDER_MCP_HOST=127.0.0.1 --env BLENDER_MCP_PORT=9877 --env BLENDER_PATH=C:\Work\Codex\KidsGame\.tools\blender-5.1.2-windows-x64\blender.exe -- C:\Work\Codex\KidsGame\.tools\blender-mcp-venv\Scripts\blender-mcp.exe
```

После обновления подключений/новой сессии Codex доступны инструменты MCP.
В уже открытой сессии работает тот же официальный сервер через клиент:

```powershell
& './.tools/blender-mcp-venv/Scripts/python.exe' scripts/blender-mcp-call.py --list
& './.tools/blender-mcp-venv/Scripts/python.exe' scripts/blender-mcp-call.py --script scripts/render-milo-study.py
```

`--script` исполняет Python **в Blender**. Используйте только проверенный код.
Ограничения официального аддона сохраняются.

## Исходники и следующие этапы

`setup-milo-authoring.py` создаёт чистую сцену и отказывается перезаписывать
существующую. `model-milo-head.py` документирует создание текущего этюда;
после ручных правок его нельзя запускать для пересоздания модели. Он разрешает
только переход от своего нетронутого v3 к v4, сохраняя копию v3 в `.test-artifacts/`.
`model-milo-outfit.py` создаёт одежду на v4 головы или исправляет нетронутый
первый этюд одежды. `refine-milo-study.py` корректирует только v2 полного этюда.
`finish-milo-study-checkpoint.py` добавляет подкладку и очищает контрольную сетку
только на v3 полного этюда. Итог сохранён как v4.
Все эти скрипты имеют проверки состояния и сохраняют предыдущую версию.
`render-milo-study.py` рендерит три дополнительных ракурса без замены геометрии.

Порядок: довести лицо и силуэт → тело/отдельная одежда → UV и материалы →
риг и семь различимых анимаций → проверка GLB в `/__cat-import-review` →
утверждение CAT → остальные животные. Подробная приёмка — `CAT_ART_HANDOFF.md`.

`.tools/` и `.test-artifacts/` не публикуются. В исходниках нет учётных данных;
установочный скрипт обращается только к публичным дистрибутивам. ISP этим
процессом не изменяется.

## Пробная локальная реконструкция по изображению

Чтобы проверить более близкую к референсу форму, отдельно исследуется
[TripoSR](https://github.com/VAST-AI-Research/TripoSR). Код и веса опубликованы
под MIT. Это локальная нейросеть, не Tripo API; картинка не загружается в
сервис генерации. Веса и открытая конфигурация скачиваются при подготовке,
сегментация фона выполняется внутри локального процесса.

На текущем компьютере GTX 1050 Ti с 4 GB, поэтому пробный запуск использует
CPU. Нужны Python **3.11**, место для весов (~1.6 GiB) и среды, достаточно
свободной оперативной памяти. При реконструкции сохранённый фоновый Blender
временно остановлен для освобождения памяти; после проверки его можно запустить
командой выше.

```powershell
./scripts/prepare-milo-reconstruction.ps1
& './.tools/triposr-venv/Scripts/python.exe' scripts/reconstruct-milo-local.py --resolution 128
```

Закреплены commit `107cefdc244c39106fa830359024f6a2f1c78871`,
ревизия весов `5b521936b01fbe1890f6f9baed0254ab6351c04a` и SHA-256
`429e2c6b22a0923967459de24d67f05962b235f79cde6b032aa7ed2ffcd970ee`.
На Windows вместо компиляции CUDA marching cubes используется CPU-адаптер
PyMCubes с преобразованием порядка осей. Архитектура и веса не изменены.

Выход — сырой `milo-draft.glb`/PLY и отчёт в `.test-artifacts/milo-reconstruction-128/`.
Это **не** готовый персонаж: нужны визуальная проверка, разделение материалов,
ретопология, одежда, глаза, мех, риг и анимации. Полезность результата определяется
после осмотра настоящей сетки в Blender; неудачную реконструкцию нельзя подменять
ею текущий CAT или выдавать за художественный эталон.

Локальные пробы 128 и 256 завершены. Сцена для осмотра плотной сетки —
`assets/characters/cat/milo-reconstruction-256.blend`, 98 504 треугольника.
Четыре настоящих ракурса сохранены в `.test-artifacts/milo-reconstruction-256/`.
Силуэт узнаваем, но поверхность неровная, глаза не разделены, ворс и риг отсутствуют.
Это промежуточный материал для доработки, не утверждённый CAT.

На отдельном компьютере с подходящей NVIDIA GPU скрипт поддерживает
`--device cuda`. Нужна отдельная среда с CUDA-сборкой PyTorch, совместимой с
драйвером этой машины; установщик выше создаёт только CPU-среду.
Маршинг кубов остаётся на CPU, инференс и запросы цвета выполняются на выбранном
устройстве. CUDA-ветка подготовлена, но ещё не проверена на удалённой GPU.
Файл `доступ ssh.txt` игнорируется Git и не передаётся вместе с ассетами.

Отдельно выполнен опыт `scripts/refine-milo-reconstruction.py`:
`assets/characters/cat/milo-eye-study.blend`, результат рендера в
`.test-artifacts/milo-eye-study-front.png`. Результат **не принят**: накладные
глаза выглядят круглыми, чужеродными и не решают неровную форму реконструкции.
Не экспортировать эту сцену в игру и не использовать её как CAT-эталон.
Следующая работа должна менять топологию мордочки и посадку глаз как единую
форму, сохраняя независимую оптику глаза, а затем перейти к одежде, ворсу и ригу.

Повторная проба `milo-eye-study-v2.blend` слегка разгладила исходную сетку и
углубила/увеличила оптические элементы, но рендер всё равно показывает
«наклеенные» круглые глаза. Она тоже **отклонена**. Продолжать подбирать кольца
радужки поверх TripoSR не имеет смысла: нужна другая геометрическая основа.

`scripts/sculpt-milo-sockets.py` выдавливает области глаз в основной сетке и
ставит объёмные глаза в получившиеся углубления. Это исправляет отдельную
проблему наложения, но форма головы и шерсти по-прежнему слишком грубая;
`milo-socket-study.blend` не является финальной моделью.

`scripts/project-milo-turnaround.py` использует **оригинал** утверждённого
трёхракурсного рисунка как атлас поверх черновой 3D-формы, не изменяя пиксели
изображения. Передний вид стал ближе к нужному дизайну, однако проекция даёт
заметные швы, несовпадения глаз/одежды и фрагменты фонового цвета на лапах
и хвосте. `milo-projection-study.blend` — только доказательство того, что
оригинальный рисунок может дать детали материалов; готового UV, ретопологии,
грума и рига в сцене нет. Не экспортировать её в приложение.
`scripts/blend-milo-projection.py` создал вторую сцену
`milo-projection-blend-study.blend` с плавным смешиванием видов по нормали и
возвратом к исходному цвету на нейтральных областях. Она уменьшает швы,
особенно сзади и по плечам; три ракурса сохранены в `studies/`. Но передние
глаза всё ещё искажены, кисти/ступни и хвост слишком примитивны, а карта
текстуры зависит от направления поверхности. Эта сцена тоже **не принята**.
Дополнительный локальный опыт с глазными яблоками, текстурированными из
оригинального рисунка, показал двойные контуры; скрытие плоской подложки
создало пятна на мордочке. Результат отклонён и не публикуется как ассет.
Следующий шаг — ручная форма лица с чистыми разрезами век и UV, отдельный
текстурный атлас и только затем грум/ткань/риг. Скриптовое наложение поверх
сырой сетки эту задачу не решает.

## Следующий кандидат для исходной формы

Официальный [Microsoft TRELLIS](https://github.com/microsoft/TRELLIS) имеет
MIT-лицензию для большинства кода и моделей и пример
[`run_multi_image`](https://github.com/microsoft/TRELLIS/blob/main/example_multi_image.py).
Это позволяет отдельно подать согласованные фронтальный, боковой и задний
ракурсы утверждённого Milo. Разработчики указывают NVIDIA GPU с **минимум
16 GB VRAM** и проверенный **Linux**; Windows-сборка не гарантирована.
Удалённый Windows-хост `192.168.88.27` доступен по SSH: i7-12650H, 32 GB RAM,
RTX 3050 Laptop с **4 GB VRAM**, Python 3.13, Git и около 216 GB свободного
места на C:. Полноценного Linux-дистрибутива WSL не обнаружено (есть только
`docker-desktop`). Это лучше для CPU-задач, но **не отвечает минимуму TRELLIS**.
На этом хосте не следует ставить его 16+ GB весов в надежде на быстрый GPU.
Даже удачная реконструкция останется
черновой: мордочку, мех, ткань, топологию для рига и семь движений нужно
довести в Blender и проверить в Safari.

TripoSR 256 и обе пробы глаз оставить только как сравнительные этюды. Не
подменять ими `public/models/cat-studio.glb` и не переходить к другим видам.
